## 错在哪

数值本身写错的很少（十几条）。多数瑕疵是：引错章节或表、条件漏写（单位电压、污染等级、某型号才成立）、规则句子比来源说得更绝对、把同一份来源里邻近的数字当成了目标数字、`check` 与 `parameters` 的阈值不一致。有代表性的修正：

* `PWR-PLC-005`：缓冲电路电阻公式写成 √(Lp/Cp)，来源（TI SLUA851A，公式与算例）是它的一半 0.5·√(Lp/Cp)。
* `PWR-FLR-002`：规则正文的保险丝 / TVS 顺序与自己的检查文字相反，已统一。
* `ANA-SCH-007`：HX711 的 0.1 µF 电容接错了脚（数据手册图 1 是 AVDD 上 10 µF、VBG 脚上 0.1 µF）。
* `HVS-ARC-003`：偶发凝露仍属污染等级 2，规则里写成了 3；`HVS-RTE-002`：开槽最小宽度随污染等级（0.25 / 1.0 / 1.5 mm）；`HVS-RTE-003`：1.5 / 3 mm 的间隙经验值只符合 IEC 60664-1，IEC 62368-1 更严（基本绝缘 1.8 mm、加强绝缘 3.6 mm）。
* `LPW-SCH-005` 与 `AUD-SCH-012`：阈值方向（`<=` / `>`）写反或把"大于"写成"大于等于"。
* `GEN-ARC-008`、`GEN-SCH-007`：复位时序检查用错了阈值（应以 VIL_nRST 为 tSTBL 终点）。
* `DFM-PLC-002`（与来源矛盾）、`DFM-MFG-011`（阈值在来源里找不到）：参数已删除，`confidence` 降级。
* `RF-FLR-001`：示例板天线禁布区的数字没有出处，改为 Espressif 图里的尺寸；`RF-RTE-001`：来源只"推荐"，规则文字从"必须"改为"应"。
* `GEN-RTE-001`：延伸 ≥2h、建议 5h 是目录自己的取值，不是来源的，标为目录推导并把 `confidence` 降为 `medium`。
* `GEN-VER-003`：手册与参考表对 `footprint_filter` 的 ERC 默认严重级别说法不一致；实测（KiCad 10.0.6，无 `.kicad_pro` 的裸工程）该项在 `ignored_checks` 里，已记入 `conflicts`。

## 没有核对到的

* **付费标准**（IPC-2221/2152/7351、IEC 60664-1/62368-1/61000-4-x、JEDEC）的原文没有读，用的是厂商应用笔记、论文和第三方转载（如 smps.us 的爬电表，数值与脚本一致，4 行还与 TI SLUP419 表 3 吻合，但不等于读过标准）。
* **在审计者的网络里打不开的站点**：analog.com（MT-031、Zumbahlen 文章、AN-88 等）、部分 st.com、edn.com / eetimes.com、Nordic DevZone、FCC KDB。这些来源只能通过镜像、检索摘要或 WebFetch 摘要核对，相关规则的 `confidence` 已按此标注（`medium`），无法核对的有 3 条。
* 审计是**读来源再比对**，不是独立复现实验；审计者也可能读错。把某个数值变成硬性门禁前，仍请打开来源再看一眼。

## 已知的遗留问题（没有改）

* `HSD-RTE-012` / `HSD-RTE-013`：DDR3 的 ±20 / ±10 mil 偏斜窗口在 `check` 里被当成单边最大值，而 KiCad 的 skew 是相对最长网络量的，所以检查偏保守，可能把合规设计判为不合格。
* `RF-RTE-005`（要求射频线下方整块地）与 Nordic 的"内层挖空"做法冲突，`RF-PLN-005` 已记录，但 `RF-RTE-005` 本身没有交叉引用。
* `GEN-PLC-007`：`severity: consider`，但 `conflicts` 文字说要按 "should" 执行。
* `EMC-FLR-006`：线缆辫子电感与 dB 数值没能核对（来源页返回空），`confidence` 为 `low`，数值保持不可信。
